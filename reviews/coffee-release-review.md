# v0.3.8 咖啡数据库演示交叉审查

审查日期：2026-11-01。范围：v0.3.7 后的数据库、预测调用、结果卡与报告指引变更。

三路独立审查分别覆盖 Python 预测、界面与报告、宿主与分发。预测审查发现问题后修复，由分发审查者再次检查。主 agent 执行最终构建、测试和发布核验。

## 改动范围

- data：设置页支持演示标识；MySQL DATE 保留日历字符串。
- tool：上传前时序预检、重复命令词容错、无真值基线判断、报告缺列指引与点预测合计。
- agent：本地 error-only 返回显示失败状态。
- preset：统一程序复算报告数字，补充分位数、因果归因和备料建议边界。
- cover：没有功能变更，仅随套件更新版本。

数据库模拟数据、报告、会话和截图保留在仓库外，不打入插件。

## 审查发现与修复

| 问题 | 影响 | 修复与验证 |
| --- | --- | --- |
| 非有限分位点触发 OverflowError | `--levels inf` 不能走统一参数错误输出 | 先检查有限性与范围；8 组非法分位参数在上传前拒绝 |
| 新 CSV 预检只接受 UTF-8 逗号格式 | 收窄原上传入口对表格的兼容范围 | 支持逗号、分号、制表符、竖线及 UTF BOM；16 组编码与分隔符组合通过 |
| 报告指引只写“汇总杯数” | 通用报告措辞偏向咖啡场景 | 改为“汇总数量（如杯数）”，规则仍仅作用于 LimiX 模式 |

CSV 仍严格拒绝缺列、重复列和行宽不一致。无 BOM 且非 UTF-8 的编码不猜测，打印明确提示后交服务端校验。远端数据版本和非 CSV 内容也由服务端校验；非 ISO 日期需指定 `--date-format`。预检不会修改输入文件。
