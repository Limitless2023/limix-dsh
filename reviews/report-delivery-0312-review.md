## 已完成的工程修复

- report 在指定目录独占创建同名 HTML 和最终 Markdown。历史副本使用相同内容，Markdown 含程序核验附录。
- Markdown 冲突时移除本次创建的 HTML，不修改原稿、已有文件或符号链接目标。
- 回执增加 markdown_saved_to、preview_format、preview_instruction。下载通道登记最终 Markdown。
- SVG 使用结果卡或浏览器预览；工作流不再将其传给仅支持位图的 read_image。
- 成功报告回执中登记的预览文件读取失败，显示“报告已生成，预览检查未完成”。其他失败仍显示未完成；失败记录不删除。

## 验证

完整构建、Node/Python 测试、五包打包及树外载入检查通过。新增双格式一致性、文件冲突回滚、预览失败与其他失败隔离测试。

独立 DSH Web 环境使用五个候选包，DeepSeek-V4.1-Flash / Max。通过界面提交“复用钢材预测生成 HTML 和 Markdown，不重新预测”。报告工具在指定目录生成两份最终文件；与稳定历史副本逐字节一致。未再次发生 SVG read_image 错误，任务流程显示已完成。旧版本保留，没有覆盖输入。

此项复用了已有真实预测 CSV，不代表重新验证全部预测 API。测试位于独立 Web profile，不在日常 desktop 会话中。最终提示词又增加了方法前提与历史材料证据原则，这部分使用 headless 复测，不冒充该次界面的同版验证。

## 提示词结果与发布阻塞

提示词按业务决定、证据范围、方法前提组织，没有加入针对钢材或促销字段的禁令。初轮八类场景、随后八类表达复测和四类证据原则复测均保留原始问答，不以退出码代替质量评分。

- 限定 CSV 检查最终准确识别三行、三列和一个空值，没有预测或生成报告；仍有可删的格式说明。
- RMSE 方向、R² 非准确率、缺数据不伪造预测等检查通过。
- 促销咨询仍会把未经确认的促销分配机制当成事实，并提前推荐准实验方法；关键条件未充分核对。
- 钢材报告生成后自行纠正了样本强度排序表述，但最终正文仍包含“待预测文件不含目标列，不构成目标泄漏”，不能据此认定整体无泄漏。
- 首轮限定检查还出现非空数量与缺失数量矛盾；后续复测未重现，不能据单次改进宣称稳定解决。

初次验收因上述问题暂缓发布；用户随后明确批准保留已知限制发布。工程修复通过与模型文字可信度分开记录，不将报告生成成功当作正文验收通过。
